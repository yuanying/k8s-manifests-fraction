## 8. 手順書との差、気づいたこと

- §5.2 の 4: .112 は etcd のリーダーだったので、`unset ETCDCTL_ENDPOINTS` の形で `move-leader` を流し、.113 へ移した（3 秒で終わった）。再起動の間に選挙は起きず、raft term は move-leader の分の 1 つだけ進んだ。VIP の失敗は .113（リーダーでない）と同じ 6 回で、dev のリーダーの .112 の 8 回（move-leader が止まったまま再起動した）より少なかった
- §5.2 の 3: 消した controller-manager がリーダーだったため、代わりが作られるまで 26 秒かかった（3）。runbook §5.2 の 3 に書き足した
- §5.3: control-plane の再起動の間に、leader election を使う controller（gated、Longhorn の CSI の sidecar）が lease を更新できずに 1 回再起動することがある。gated が再起動すると gated の LoadBalancer が一瞬途切れる（4.1）。.113 でも CSI の sidecar が 2 つ再起動していた。runbook §5.3 と §5.2 の 10 に書き足した
- 作業端末の `LC_ALL` は `unset LC_ALL` してから SSH した（runbook §1.2）
