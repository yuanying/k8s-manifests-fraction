## 8. 手順書との差、気づいたこと

- §5.2 の 6、§8.4: **arm64 の `containerd.io` 2.3.6 は amd64 と同じ形で入り、同じように動いた**。模擬の結果、conffile の扱い（`Using current old file`）、config の md5、`config dump`、runc 1.5.1、containerd の commit（`ee27353…`）、journal に出るもの、kubelet の再起動で Pod が止まらないことが、amd64 と同じだった
- §5.2 の 3: controller-manager と scheduler は 1 つずつ消して、どちらも .111 に移った（14 秒と 21 秒）。**この結果、.111 と .112 に 1 つずつ、.113 には無い配置になった**。.112 の作業では、.112 の 2 つは .113 に移る見込み（.111 には既に 1 つずつあり、anti-affinity が preferred のため）。.111 の作業の時点では .111 と .113 に 1 つずつになる見込みで、.111 の 2 つは .112 に移る
- §5.2 の 4: .113 は etcd のリーダーではなかったので、`move-leader` は流していない。**.112 はリーダー（2026-10-18 10:46Z）なので、.112 の作業で `move-leader` を流すことになる**。移す先は次に作業しない .113（`57ec6f12ac7b683e`）。runbook §5.2 の 4 に書いた
- §5.2 の 9、§5.3: Pi 5 の再起動は 44 秒で Ready に戻った。VIP の失敗は 28 秒の間に 6 回で、dev の見込みの範囲。.113 は MetalLB の告知を持っていなかった
- §5.2 の 10: cnidaria は CrashLoopBackOff にならず、speaker が 1 回だけ落ちた（oeilvert と同じ）
- 作業端末の `LC_ALL`（en_US.UTF-8）が SSH で渡ると、Pi では `bash: warning: setlocale: LC_ALL: cannot change locale` が出る（Pi に en_US.UTF-8 のロケールが無い）。害は無い。`unset LC_ALL` してから SSH すると出ない（cnidaria の手順書の `common.sh` と同じ扱い）
