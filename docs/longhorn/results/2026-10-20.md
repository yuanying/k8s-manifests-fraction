### 3.3 一時的な作り直し

12 個のうち 7 個で、CR を消した約 3 秒後に Longhorn が同じ名前の orphan を新しい uid で作り直し、20〜25 秒後に自分で消した。

- 作り直したのは `longhorn-service-account`（duchamp の manager の webhook のログに `operation: CREATE`）。作り直した CR は `spec.nodeID` の manager がすぐ引き取り（`Orphan got new owner oeilvert`）、20〜25 秒後に削除され、同じパスでもう一度 `Deleting orphan … replica data store …` と `OrphanCleanupCompleted` を出した（イベントは同じ名前で uid が 2 つ。`notes/longhorn-fix/orphan-events.txt`）。そのときディレクトリはもう無かった
- 作り直された 7 個も、60 秒後の確認では CR は無く、ディレクトリも無い。#8 から #10 では、`kubectl delete` の 3 秒後の `get` で作り直した CR が見えた
- 原因は確かめていない。ディスクの監視（30 秒ごと）が削除の前に読んだディレクトリの一覧を node controller が使って CR を作り、次の読み取りでディレクトリが無くなったので消した、と見ている（手順書 §3.3 の作り直しと同じ経路で、タイミングで起きたり起きなかったりする）
- データには影響しない。作り直した CR を消すときも、消すのは同じ `<DiskPath>/replicas/<DataName>` だけ

### 3.4 最後の確認（04:09〜04:10）

- `kubectl -n longhorn-system get orphans.longhorn.io` は `No resources found`
- 12 個のディレクトリはノードですべて `gone`
- Volume・Replica・Engine・ShareManager・`longhorn-system` の Pod が作業の前と同じ（§1）
